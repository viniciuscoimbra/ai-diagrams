Sistema de cobrança por boleto: contêineres e dependências

Quem usa o sistema de cobrança, em que contêineres ele se divide e de que sistemas ele depende, da emissão do boleto à baixa pelo arquivo de retorno. Cada seta é uma relação numerada, com a tecnologia ao lado; o que cada uma faz está em "Relações". Pix cobrança, protesto e negativação ficam fora do desenho.

Relações
1
Cliente PJ → Portal PJ. Emite boletos em lote e acompanha os recebimentos.
2
Cliente PJ → API de cobrança. Integração direta do sistema do cliente para emitir e consultar boletos.
3
Portal PJ → API de cobrança. Envia o pedido de emissão e consulta a situação dos boletos.
4
Analista financeiro → Backoffice. Trata boleto pago em duplicidade e devolução.
5
Backoffice → API de cobrança. Usa a mesma API, com o papel de operador.
6
API de cobrança → CIP. Registra cada boleto antes de devolver a linha digitável.
7
API de cobrança → Banco de cobrança. Grava o boleto, a situação e o evento de emissão.
8
Banco liquidante → Processador de retorno. Deposita o CNAB 240 por SFTP num bucket; o evento do bucket vai para a fila do processador.
9
Processador de retorno → Banco de cobrança. Dá baixa no boleto e grava o evento de pagamento.
10
Processador de retorno → Webhook do cliente. Avisa o cliente PJ a cada boleto pago, com assinatura HMAC.
11
Processador de retorno → ERP contábil. Publica o lançamento de cada baixa como evento.
