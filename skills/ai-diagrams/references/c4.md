# C4

Um sistema visto em camadas: quem usa, em que partes ele se divide e de que outros sistemas depende. Segue o modelo C4 de Simon Brown, nos níveis 1 (contexto) e 2 (contêineres). Usa o pipeline do poster (`assets/estilo.css`, `scripts/build.py` e o gate `poster_lint.py`).

Modelo: `modelos/11-c4/`, na pasta da skill. Ele é de nível 2.

## Quando usar

- "C4", "diagrama de contexto", "diagrama de contêineres", "visão de sistema";
- apresentar um sistema para quem não conhece: o que está dentro, o que está fora e como cada parte conversa;
- documentar dependências entre sistemas de times diferentes.

Se o assunto é a infraestrutura AWS (rede, conta, região, serviço gerenciado), é poster de arquitetura. Se é a ordem das chamadas numa operação, é sequência. O C4 fica entre os dois: a caixa é uma parte do software, não um recurso de nuvem.

## Níveis

- **Nível 1, contexto:** o sistema em foco é uma caixa só, no centro. Em volta ficam as pessoas e os sistemas externos. Não há `.frame.limite`.
- **Nível 2, contêineres:** o sistema em foco vira um `.frame.limite` com os contêineres dentro (app, API, worker, banco, fila). Pessoas e sistemas externos ficam fora do limite.
- Nível 3 (componentes) e 4 (código) ficam fora desta skill. Se o pedido descer até classe ou módulo, diga isso e ofereça o nível 2.

## Elementos

Todo elemento é um `.bchip.c4` com três linhas: `.bn` (tipo e tecnologia), `.bt` (nome) e `.bs` (o que faz, em uma frase curta).

| Elemento | Classe | Tipo em `.bn` |
|---|---|---|
| pessoa | `bchip c4 pessoa` | `pessoa` |
| sistema em foco, no nível 1 | `bchip c4` | `sistema · <dono>` |
| contêiner | `bchip c4` | `contêiner · <linguagem ou plataforma>` |
| contêiner de dados | `bchip c4 banco` | `contêiner · <banco>` |
| sistema externo | `bchip c4 externo` | `sistema externo · <dono>` |
| limite do sistema, no nível 2 | `frame limite` com `.flabel` | `<nome> · sistema em foco` |

- Ícone AWS opcional no canto do contêiner (`<img src="aws://...">`), só quando a plataforma é AWS. Pessoa e sistema externo não levam ícone.
- Tamanho: 260 × 96 px para o contêiner, até 110 px de altura se a descrição tiver duas linhas. Mesmo tamanho para os elementos de uma mesma linha.

## Relações

- Toda seta é uma relação numerada: badge em cima da linha e um item em `.passos` com o título "Relações".
- O item diz `<origem> → <destino>.` em negrito e, em uma frase, o que a relação faz.
- Ao lado da seta vai só a tecnologia, num `.elabel.tec`: `HTTPS · JSON`, `SQL`, `gRPC`, `ICOM · mTLS`. Frase vai no item de "Relações", não no rótulo.
- A seta sai de quem chama e aponta para quem é chamado. Resposta não ganha seta própria.

## Legenda

A página termina com a seção "Legenda C4" (`<div class="sec">Legenda C4</div>` e `<div class="c4leg">`), só com os elementos que aparecem no desenho. Copie do modelo.

## Comandos

Comece copiando `modelos/11-c4/_src/11-c4-pix.html` e troque o conteúdo. O `<head>` do modelo traz o marcador `/*ESTILO*/`, que o build troca pelo CSS. Sem o marcador, o build para com `SEM-ESTILO`.

```bash
python3 <skill>/scripts/build.py diagramas/_src/NN-nome.html
```

Gate: o do poster (lista em `SKILL.md`), com duas réguas a mais:

- `C4-SEM-TIPO`: elemento `.bchip.c4` sem `.bn` ou sem `.bt`;
- `C4-SEM-LEGENDA`: página com elemento C4 e sem `.c4leg`.

## Na leitura do PNG

- quem está dentro e quem está fora do limite se vê sem ler os rótulos;
- toda pessoa e todo sistema externo tem pelo menos uma relação;
- a tecnologia ao lado da seta não encosta na caixa de destino nem na borda do limite;
- "Relações" conta o sistema sem precisar do desenho.
